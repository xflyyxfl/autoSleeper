# autoSleeper · 睡眠守护

监听 Haylou Solar LS05 手环的心率，判断是否入睡；入睡后发广播，由 Tasker / AutoJS 接手暂停播放并锁屏。

## 为什么不是"实时心率"

公开协议文档（[eralpozcan/haylou-ls05](https://github.com/eralpozcan/haylou-ls05)）里写的实时心率命令是写单字节 `0x16`，回 `16 11 00 <bpm>`。**这条在本文手环的固件 `RH192HAV001836` 上完全无效**——写进去没有任何回应。文档验证的是另一个固件 `RH192IBV003006`。

手环也不提供"当前是否睡着"这个字段：睡眠事件是固件把一段数据密封之后才给的。

于是只剩一条可行路径：**让手环自己记录，我们事后拉曲线。**

## 真正在用的机制

手环内部把心率按 **10 分钟一格**聚合，写进一张按"当天 00:00 起算"的固定表里（一天 144 格）。这张表可以用一条命令整表拉回来，里面就有睡眠期的心率。

| 命令 | 作用 |
|---|---|
| `20 01` | **解锁**。连接后必须先发，否则后面所有命令被静默丢弃 |
| `18 01` | 开启心率监测（LED 亮，开始采样） |
| `18 02` | 关闭心率监测。**不是 `18 00`**，发 00 会被当未知指令丢掉 |
| `18 fa` | 拉取整张心率表 |

`18 02` 这个值是反编译 `Lw/h1;-><clinit>` 得到的：`transient=[0x01]` 是开、`implements=[0x02]` 是关。
同样从 `Lo0/com1;` 里查到 App 的默认监测时段是 08:00–21:00，所以"夜里没数据"不是故障，是它根本没开。

### 拉回来的帧

```
18 04 07 <y m d> <hh> <mm> <?> <crc16>    摘要，带手表当前时间
18 07 <y m d> <seq> <12 字节>              数据，seq=2,4,6…，idx=(seq/2-1)*12
18 fd <crc>                                结束
```

每格 10 分钟，`0xFF` 表示这一格没数据。包数随时间推移增长（实测 11:33 回 6 包、13:41 回 8 包），所以缓冲区按整天 144 格预留。

## 省电：只亮一小段

连续开着监测的话 LED 会整夜常亮，本来能撑一周的表一天就没电。实测出来的规律是：

1. **关闭监测不会清空已经写好的格子**，只丢弃当前还没结算的半格；
2. 一格只要在**结算时刻（每 10 分钟整）前后**处在监测状态，就能落盘——实测只亮 **90 秒**、在上整点前 5 秒关掉，这一格照样写进去了；
3. 所以采用**对齐整点、每 10 分钟只亮 150 秒**的占空比方案，`150/600 = 25%`，续航损失比常亮小一个量级。

于是每轮的动作是：

```
整点前 150 秒 → 连表、发 18 01（亮灯）
整点后 15 秒  → 发 18 02（灭灯）
再拉 18 fa    → 判定
其余时间      → 完全断开，手环正常休眠
```

连接在整点前 50 秒才建立。手环不维持空闲连接，实测空闲 11 分钟必断；等待期间也会每 40 秒发一次电量查询当心跳。另外**扫描要放在临近整点**，提前几分钟扫到再等，会因为广播缓存过期而连不上。

## 判定逻辑

每轮把最近几格心率交给打分器：

| 项 | 条件 | 分值 |
|---|---|---|
| 下行 | 中位数 ≤ 基线 − 5 bpm | +40（微降 +20） |
| 平稳 | 标准差 < 3 | +20（>6 扣 15） |
| 未回升 | 中位数 ≤ 上一窗 + 1 | +20（明显回升扣 20） |
| 无突升 | 最大值 ≤ 基线 + 12 | 否则扣 25 |

得分 ≥ 60 且**连续 2 个窗口**成立 → 判睡。基线在清醒时缓慢跟随，判睡后锁定。
默认窗口 3 格 = 30 分钟，所以判定延迟在 20~30 分钟量级——受限于手环 10 分钟的聚合粒度，不是算法问题。

## 使用

1. 安装 APK，授予蓝牙权限（Android 12+ 是「附近的设备」，不是定位）。
2. 手机蓝牙里的 `Haylou Solar` 保留配对；连不上就点界面里的「系统配对」。
3. 睡前点「开始守护」。建议给本应用加电池白名单，否则国产 ROM 会杀后台。
4. 先点「立即测一次」确认能读到曲线，再开始守护。

> 守护期间手环被本应用独占，Hello Haylou 连不上。白天要同步数据时先停守护。

## 给 Tasker / AutoJS 的接口

三种广播，Tasker 里用「事件 → 系统 → 收到的意图」监听：

| 广播 | 时机 | 附加数据 |
|---|---|---|
| `com.vlab.autosleeper.ASLEEP` | 判定入睡（每次入睡只发一次） | `bpm` `score` `at` |
| `com.vlab.autosleeper.AWAKE` | 从睡眠中恢复 | `bpm` `score` `at` |
| `com.vlab.autosleeper.STATE` | 每一轮结果 | `bpm` `score` `asleep` `at` |

同时写 `/sdcard/Android/data/com.vlab.autosleeper/files/state.txt`，格式 `asleep,62,80,1732...`。

收到 ASLEEP 后可以执行（需一次 ADB Wifi 配对）：

```sh
am force-stop com.netease.cloudmusic   # 或对应播放器包名
input keyevent 26                      # 电源键锁屏
cmd media_session dispatch pause       # 兜底停播
```

## 已知限制

- 心率依赖佩戴，表带松了拉到的是空值，此时不会误判入睡（会跳过本轮）。
- 格子结算依赖手环自身时钟，若手表时间被改乱，格号会对不上。
- 判定粒度下限就是 10 分钟一格，再快没有意义。
