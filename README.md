# autoSleeper · 睡眠守护

监听 Haylou Solar LS05 手环的心率，判断是否入睡；入睡后发广播并自动锁屏，由 Tasker / AutoJS 接手暂停播放。

## 界面与功能（v2.0）

- **心率曲线**：自绘最近 12 小时（72 格）的曲线，空格断线，叠加阈值线，底部标出时刻。
- **判定规则**：心率低于阈值 **M** 持续 **N** 格 → 判睡，需连续 `确认轮数` 轮成立才真正触发，避免单次误采。
  另有「相对基线四票打分」作为高级模式，勾选「基线打分模式」后启用。
- **测一次**：点一下开灯，按设置的 **亮灯时长** 跑，到点自动收尾；**期间可随时点「结束」提前收尾**。
  两种收尾走同一条后续：关灯 → 拉曲线 → 判定 → 广播 →（按需）锁屏。
- **拉取**：只读。不开灯、不改手环的心率开关、不判定、不锁屏。
- **自动锁屏**：靠设备管理器 `lockNow()`。首次要点「激活锁屏权限」并在系统弹窗里同意；之后判睡会直接熄屏。
- **两种测量模式**：
  - 连续监测：心率灯全程开启，曲线连续，最准，也最费电；
  - 脉冲省电：每 10 分钟只在整点前亮 `亮灯时长` 秒，占空比约 25%，续航损失小一个量级。
- **保活**：前台服务 + WakeLock + 5 分钟看门狗 + 电池优化白名单入口。

## 代码结构（v2.0 重构）

按「一件事只有一处实现」分层，依赖方向自上而下：

| 层 | 包 | 职责 |
|---|---|---|
| 界面 | `com.vlab.autosleeper` | MainActivity、ConfigBinder、悬浮球、曲线控件。只呈现与触发 |
| 服务入口 | `com.vlab.autosleeper` | GuardService：生命周期 + 通知 + Intent 路由（约 400 行，原 674 行混杂） |
| 流程 | `flow` | GuardFlow / OnceFlow / FetchFlow，唯一持有循环的地方 |
| 原子操作 | `task` | Connect / LedOn / LedOff / FetchPulse / Judge / Publish / AutoLock，均可单独调用 |
| BLE | `band` | BandSession（唯一 GATT 出口）、PulseCodec（帧解析）、BandCommand |
| 纯逻辑 | `core` | PulseTable、PulseWindow、JudgeEngine、BoundaryClock。无 Android 依赖，可单测 |
| 数据 | `data` | ConfigSpec（唯一参数定义）、Config、PulseRepository、EventStore |

五条「唯一出口」，这是重构的主轴：

1. **BLE 会话** 只有 `BandSession`，互斥锁在 `open()` 内部，拿不到就报 BUSY。
2. **取窗口** 只有 `PulseTable.window(n)`，空洞统一保留为 `NO_DATA`，两种判定看到的是同一份数据。
3. **睡/醒状态** 只有 `ConsecutiveGate`，只在边沿返回 `FELL_ASLEEP` / `WOKE_UP`。
4. **参数定义** 只有 `ConfigSpec`，get/set/clamp/界面绑定都从它派生。
5. **对外事件** 只有 `Tasks.Publish`，广播 + state.txt + verdict.log 一次性完成。

## 为什么不是"实时心率"

公开协议文档（[eralpozcan/haylou-ls05](https://github.com/eralpozcan/haylou-ls05)）里写的实时心率命令是写单字节 `0x16`，回 `16 11 00 <bpm>`。**这条在本文手环的固件 `RH192HAV001836` 上完全无效**——写进去没有任何回应。文档验证的是另一个固件 `RH192IBV003006`。

手环也不提供"当前是否睡着"这个字段：睡眠事件是固件把一段数据密封之后才给的。

## 真正在用的机制

手环内部把心率按 **10 分钟一格**聚合，写进一张按"当天 00:00 起算"的固定表里（一天 144 格）。这张表可以用一条命令整表拉回来，里面就有睡眠期的心率。

| 命令 | 作用 |
|---|---|
| `20 01` | **解锁**。连接后必须先发，否则后面所有命令被静默丢弃 |
| `18 01` | 开启心率监测（LED 亮，开始采样） |
| `18 02` | 关闭心率监测。**不是 `18 00`**，发 00 会被当未知指令丢掉 |
| `18 fa` | 拉取整张心率表 |
| `03` | 电量查询，空等时当心跳用 |

`18 02` 这个值是反编译 `Lw/h1;-><clinit>` 得到的：`transient=[0x01]` 是开、`implements=[0x02]` 是关。

### 拉回来的帧

```
18 04 07 <y m d> <hh> <mm> <?> <crc16>    摘要，带手表当前时间
18 07 <y m d> <seq> <12 字节>              数据，seq=2,4,6…，段号 = seq/2
18 fd <crc>                                结束
```

段号映射有个坑：段 1..11 对应 00:00 起的每 2 小时，**段 0 是 22:00–24:00 那一段，固件把它排在最后发**。
早期用 `(seq/2-1)*12` 会把段 0 算成 -12 丢掉，导致 22 点之后的数据全部收不到。

## 省电：只亮一小段

实测规律：

1. **关闭监测不会清空已经写好的格子**，只丢弃当前还没结算的半格；
2. 一格内要累计约 **210 秒**以上的有效采样，且结算时刻（每 10 分钟整）监测是开着的，这一格才落盘；
3. 因此采用**对齐整点、每 10 分钟只亮 `亮灯时长`（默认 240 秒）**的占空比方案，续航损失比常亮小一个量级。

每轮动作：

```
整点前 N 秒  → 连表、发 18 01（亮灯）
整点后 15 秒 → 发 18 02（灭灯）
留 400ms     → 拉 18 fa → 判定
其余时间     → 完全断开，手环正常休眠
```

连接在开灯点前 55 秒建立；空等时每 40 秒发一次 `03` 当心跳（实测空闲 11 分钟必断）。

## 判定逻辑

默认阈值模式：最近 `窗口格数`（默认 2 格 = 20 分钟）**每一格都低于 M**，且峰值不超过 M+8；
连续 `确认轮数`（默认 2）轮成立才判睡。窗口里只要有空洞，本轮直接给「数据有缺口」，不会误判。

高级基线模式四票打分：

| 项 | 条件 | 分值 |
|---|---|---|
| 下行 | 中位数 ≤ 基线 − dropBpm | +40（微降 +20，高于基线 −30） |
| 平稳 | 标准差 < 3 | +20（>6 扣 15） |
| 未回升 | 中位数 ≤ 上一窗 + 1 | +20（明显回升扣 20） |
| 无突升 | 最大值 ≤ 基线 + 10 | 否则扣 25 |

得分 ≥ 60 记为成立。低心率 + 平稳另有兜底，兜底阈值直接取用户设的 M。

## 使用

1. 安装 APK，授予蓝牙权限（Android 12+ 是「附近的设备」，不是定位）。
2. 手机蓝牙里的 `Haylou Solar` 保留配对；连不上就点界面里的「系统配对」。
3. 睡前点「开始守护」。建议给本应用加电池白名单，否则国产 ROM 会杀后台。
4. 先点「测一次」确认能读到曲线，再开始守护。

> 守护期间手环被本应用独占，Hello Haylou 连不上。白天要同步数据时先停守护。

## 给 Tasker / AutoJS 的接口

三种广播（Action 与 extra 与 v1.x 完全一致，脚本不用改）：

| 广播 | 时机 | 附加数据 |
|---|---|---|
| `com.vlab.autosleeper.ASLEEP` | 判定入睡（每次入睡只发一次） | `bpm` `score` `at` |
| `com.vlab.autosleeper.AWAKE` | 从睡眠中恢复 | `bpm` `score` `at` |
| `com.vlab.autosleeper.STATE` | 每一轮结果 | `bpm` `score` `asleep` `at` |

同时写 `/sdcard/Android/data/com.vlab.autosleeper/files/state.txt`，格式 `asleep,62,80,1732...`。

**Intent 入口**（`am start-foreground-service -n com.vlab.autosleeper/.GuardService -a <action>`）：

| action | 作用 |
|---|---|
| `...action.START` / `...STOP` | 开始 / 停止守护 |
| `...action.ONCE` | 单次测量（按设置的亮灯时长，到点自动收尾） |
| `...action.STOP_ONCE` | **提前结束**单次测量的亮灯，随后自动拉取并判定 |
| `...action.FETCH` | 只读拉取曲线 |
| `...action.RESTART` | 强制重启守护（先终止旧线程再启动） |
| `...action.TASK` | 单独执行原子操作，extra `task=connect\|ledOn\|ledOff\|fetchPulse\|judge` |

最后一条是新增的「单独调用」能力：脚本可以只点灯、只关灯、只拉取，不用跑整条流程。

收到 ASLEEP 后可以执行（需一次 ADB Wifi 配对）：

```sh
am force-stop com.netease.cloudmusic   # 或对应播放器包名
input keyevent 26                      # 电源键锁屏
cmd media_session dispatch pause       # 兜底停播
```

## 已知限制

- 心率依赖佩戴，表带松了拉到的是空值，此时不会误判入睡（会跳过本轮并给出「数据有缺口」）。
- 格子结算依赖手环自身时钟，若手表时间被改乱，格号会对不上。
- 判定粒度下限就是 10 分钟一格，再快没有意义。
- 「测一次」要真正写入一格至少需要约 210 秒，提前「结束」只能读到已有数据。
